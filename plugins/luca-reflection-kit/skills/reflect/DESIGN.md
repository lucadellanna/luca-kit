# Design decisions

Only choices that are non-obvious or that future readers might want to undo. Self-evident choices are not listed.

| Decision | Rationale |
|----------|-----------|
| Two reviewers, not one | One prompt blended Claude-side rule edits with user-facing hints and produced weaker output on both axes. Splitting by **output target** (Agent 1 writes files; Agent 2 displays text) gives each reviewer a clean mandate and makes non-overlap a property of the pipeline, not a prompt instruction. |
| Risk derived from target file type, not LLM-judged | The agent picks the `target`; the orchestrator looks the risk up in a table. Memory writes are `safe` (reversible by deleting a line); skill/CLAUDE.md edits are `ambiguous` (system-wide behavior change); hook scripts are `security-sensitive` (auto-executes shell). LLM-judged risk would drift across runs; target-based risk is stable. |
| Verbatim digest, no event ledger | An earlier draft compressed turns into a numbered event ledger. The orchestrator's selection of which events to include encoded its own blind spots into the reviewers' inputs. Sending raw turns removes the selection step. Tool outputs are still truncated (5 + 5 lines) to bound size without losing structural signal. |
| Full rule corpus passed in-prompt to each reviewer | Lets the reviewer self-filter functional duplicates at the source instead of relying on orchestrator post-hoc cleanup. Token cost is real (~1.5K per reviewer × 2) but /reflect runs rarely, and low-value findings cost more than tokens. |
| Skills + commands index passed in-prompt | The reviewer can only propose "invoke skill X" if it knows X exists. The index covers project, global, and all installed plugin skills + commands. |
| Pure-reasoning agents use `tools: []` | Omitting `tools:` grants access to every tool, which loads each tool's definition into the agent's system context and inflates token cost. The reviewers receive everything they need in the prompt; they never call tools. |
| Literal `grep -F` duplicate check at write time, not LLM-judged dedup | The reviewers already self-filter functional duplicates against the rule corpus. A literal string match before the write is the cheap backstop for re-runs and obvious repeats. Semantic dedup belongs to `/dream`, not `/reflect`. |
| No length pre-check before running reviewers | The previous design dropped runs below ~5 exchanges. With reviewers self-filtering to a quality floor, an empty digest just produces `None.` from both reviewers and the skill exits cleanly. The pre-check added a brittle heuristic for no behavior gain. |
| Free-form reviewer output, no strict JSON | The orchestrator is an LLM, not a parser. Strict JSON would add brittleness without a real upside. The field names (`evidence:`, `target:`, `proposed_change:`) are stable enough for LLM-to-LLM handoff. |
| `AskUserQuestion` capped at 4 options | Hard platform limit; not negotiable. Overflow goes to "Logged only". |
| No file-level provenance markers | The session log at `~/.claude/reflect-logs/<project>.jsonl` already records every applied change with date, target, and text. A marker comment in the rule file would pay token cost on every future context load forever, in exchange for an audit-trail query the log already serves. Provenance lives in the log, not in marked rules. |
| Coaching language is banned in user-facing hints | The hint reviewer surfaces actions, not advice. "You should X" is paternalistic and rarely actionable. "Try X next time" is concrete. |
| Quality floor on each reviewer (recurrence-or-generalisation, two-whys, mechanism-not-instance, value-adding) | Initial live runs produced many low-value findings: single-instance observations, surface symptoms, restatements of existing rules. The floor lives in the reviewer mandates so each agent self-filters before emitting, not as orchestrator post-hoc cleanup. |
| Digest stays on the user's machine | Sub-agents run inside the same Claude Code session as the orchestrator. The digest is never sent to a wider audience than the orchestrator already received. Tool outputs in the digest may contain secrets; they do not leave the user's session. |
